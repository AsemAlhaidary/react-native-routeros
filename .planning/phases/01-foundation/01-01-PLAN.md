Implement the three remaining foundation modules — all zero-dependency, self-contained, testable in isolation.

**src/win1252.ts** — per STACK.md win1252 section and ARCHITECTURE.md codec detail:
- Define two static lookup tables (NOT per-call allocations):
  - `WIN1252_TO_UNICODE: Uint16Array(128)` — maps win1252 byte values 0x80–0xFF to Unicode code points. 0x80–0x9F are the 27 special characters (Euro sign U+20AC at 0x80, smart quotes U+201A/U+2018/U+2019/U+201C/U+201D, dagger U+2020/U+2021, bullet U+2022, ellipsis U+2026, permille U+2030, etc. — use the standard Windows-1252 mapping from the Unicode Consortium). Values 0xA0–0xFF map directly to Unicode U+00A0–U+00FF.
  - `WIN1252_FROM_UNICODE: Map<number, number>` — reverse mapping for encode (Unicode code point → win1252 byte). Only the 27 special characters from the 0x80–0x9F range.
- Export two functions:
  - `export function decodeWin1252(bytes: Uint8Array): string` — iterates each byte; if byte < 0x80 returns `String.fromCharCode(byte)` (ASCII); otherwise looks up `WIN1252_TO_UNICODE[byte - 0x80]`, falling back to the raw byte value if unmapped. Use `String.fromCharCode()` (single code point), NOT `String.fromCodePoint()` (surrogate pairs — win1252 is single-byte, no surrogates).
  - `export function encodeWin1252(str: string): Uint8Array` — allocates `new Uint8Array(str.length)`, iterates each char via `str.charCodeAt(i)`; if < 0x80, direct store; otherwise looks up `WIN1252_FROM_UNICODE.get(charCode)`, falling back to `0x3F` (ASCII '?') for unmappable characters.
- IMPORTANT: include all 27 Windows-1252 special characters accurately. The full mapping for bytes 0x80–0x9F is: U+20AC, (undefined 0x81), U+201A, U+0192, U+201E, U+2026, U+2020, U+2021, U+02C6, U+2030, U+0160, U+2039, U+0152, (undefined 0x8D), U+017D, (undefined 0x8F), (undefined 0x90), U+2018, U+2019, U+201C, U+201D, U+2022, U+2013, U+2014, U+02DC, U+2122, U+0161, U+203A, U+0153, (undefined 0x9D), U+017E, U+0178. Undefined slots store 0x00 — they are never valid win1252 and should produce the raw byte on decode (the fallback path handles this automatically).
