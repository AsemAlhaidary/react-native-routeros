<objective>
Ship an Expo config plugin that makes the library one-command setup in an Expo CNG (Continuous Native Generation) project. The plugin auto-links react-native-tcp-socket and mutates the Android manifest to add the INTERNET permission and enable cleartextTraffic for plain-TCP access to RouterOS devices.

Purpose: Bare RN autolinks react-native-tcp-socket automatically, but Expo CNG consumers need a config plugin so `npx expo prebuild` produces a working native project. This plugin is the deliverable that closes EXPO-01 and EXPO-02.
Output: `app.plugin.js` + compiled `plugin/build/*` JS that Expo resolves when `react-native-routeros` is listed in app.json `plugins`.
</objective>

1. **`plugin/src/withAndroid.ts`** — export a function `withAndroidPlugin` (typed `ConfigPlugin`) that applies `withAndroidManifest`. Inside the manifest mod: (a) add the INTERNET permission by calling `AndroidConfig.Permissions.ensurePermission('android.permission.INTERNET', manifest)` (this is EXPO-02's INTERNET half); (b) set `android:usesCleartextTraffic="true"` on the `<application>` element by obtaining it via `AndroidConfig.Manifest.getMainApplicationOrThrow(manifest)` and setting `app.$['android:usesCleartextTraffic'] = 'true'` (EXPO-02's cleartextTraffic half). For EXPO-01 (auto-link react-native-tcp-socket), wrap the manifest mod in an additional `withDangerousMod('android', ...)` step whose mod runs `WarningAggregator.addWarningAndroid` or resolves `require('react-native-tcp-socket/package.json')` from `node_modules` to confirm the native module is installed, throwing a descriptive error if it is missing — this guarantees the module is present for autolinking and is NOT a no-op passthrough. Do not write manual gradle/pod linking (RN autolinking handles registration); the plugin's job is presence verification + manifest mutation.

2. **`plugin/src/withIos.ts`** — export `withIosPlugin` (typed `ConfigPlugin`). Use `withDangerousMod('ios', ...)` to verify `react-native-tcp-socket` is installed (resolve its package.json from node_modules) and emit a `WarningAggregator` warning if absent; otherwise return the config unchanged. This keeps iOS non-no-op (autolinking verification) while requiring no pod mutation.

3. **`plugin/src/index.ts`** — `import { ConfigPlugin, withPlugins } from 'expo/config-plugins'`; `import { withAndroidPlugin } from './withAndroid'`; `import { withIosPlugin } from './withIos'`; export `const withReactNativeRouterOS: ConfigPlugin<{}> = (config) => withPlugins(config, [withAndroidPlugin, withIosPlugin])`; `export default withReactNativeRouterOS`.

4. **`app.plugin.js`** (project root) — one line: `module.exports = require('./plugin/build');`.

5. **`plugin/tsconfig.json`** — standalone config (do NOT extend the root tsconfig, whose `rootDir`/`include` are scoped to `src/`). Use `expo/config-plugins` types only — do not import from `expo` top-level in a way that would pull in RN runtime, and do not add `expo-module-scripts` (rejected in STACK.md "What NOT to Use").

<threat_model>
## Trust Boundaries

| Boundary | Description |
|-------------|-------------|
| consumer app.json `plugins` → plugin code | Expo runs the plugin at `prebuild`; plugin output mutates the consumer's native Android manifest |
| dev machine → npm registry | `npm install --save-dev expo` pulls a build-time dependency |
| app → RouterOS device (plain TCP 8728) | cleartextTraffic=true permits unencrypted traffic when the consumer chooses plain TCP |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-06 | Information disclosure | `android:usesCleartextTraffic="true"` (plain-TCP 8728) | high | mitigate | Deliberate tradeoff: plain TCP is required for RouterOS port 8728 access. The library defaults to TLS on port 8729 when `tls` options are provided, and README (05-02) recommends TLS for anything beyond a trusted LAN. The plugin only enables cleartext at the Android manifest level — it does not force consumers to use plaintext |
| T-05-07 | Elevation of privilege | INTERNET permission scope | low | accept | INTERNET is required for any TCP/TLS socket; it grants no additional privileges beyond network access and is the standard permission for networking modules |
| T-05-08 | Spoofing | self-signed TLS certificate acceptance (TLS 8729 path) | medium | mitigate | Library accepts consumer-provided CA via `tls.ca` in IRosOptions; no bundled CAs are shipped (per Out of Scope), so the consumer controls trust |
| T-05-09 | Tampering | plugin `withDangerousMod` node_modules resolution | low | accept | Plugin only reads `react-native-tcp-socket/package.json` for presence verification; it performs no filesystem writes beyond the manifest mutation Expo already sandboxes |
| T-05-SC | Tampering | npm install (expo devDependency) | high | mitigate | slopcheck + blocking human checkpoint for any [ASSUMED]/[SUS] package; keep T-SC row as the standing supply-chain gate |
</threat_model>
