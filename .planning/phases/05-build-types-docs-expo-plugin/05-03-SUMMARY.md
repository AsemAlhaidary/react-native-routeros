## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corrected reversed argument order in the plan's `ensurePermission` call**

- **Found during:** Task 1 (withAndroid.ts implementation)
- **Issue:** The plan action specified `AndroidConfig.Permissions.ensurePermission('android.permission.INTERNET', manifest)`, but the installed @expo/config-plugins v57 signature is `ensurePermission(androidManifest, permissionName)` — the arguments were reversed and would have passed a string where the manifest object was expected.
- **Fix:** Used `AndroidConfig.Permissions.ensurePermissions(manifest, ['android.permission.INTERNET'])` (plural form, matching the plan-checker warning), which mutates the manifest in place with the correct argument order.
- **Files modified:** plugin/src/withAndroid.ts
- **Verification:** Dry-run on a synthetic manifest confirmed INTERNET was added and cleartextTraffic set to 'true'.
- **Committed in:** 6c14409 (Task 1 commit)

**2. [Rule 2 - Missing Critical] Added `plugin/build/` to .gitignore**

- **Found during:** Task 2 (build:plugin compilation)
- **Issue:** The plan produced `plugin/build/*` output but the project already gitignores its library build output (`lib/`). Leaving `plugin/build/` untracked would have surfaced as untracked build artifacts on every build.
- **Fix:** Added `plugin/build/` to `.gitignore`, consistent with the existing `lib/` convention. Build output remains shipped via package.json `files` and regenerated by `npm run build`.
- **Files modified:** .gitignore
- **Verification:** `git check-ignore plugin/build/index.js` returns the path; `git status` is clean of build artifacts.
- **Committed in:** 3ef6491 (Task 2 commit)
